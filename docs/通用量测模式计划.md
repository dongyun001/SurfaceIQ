# 通用量测模式计划（检具 → 量具）

> **本文是"打算做、还没做"的计划，不是决策记录。** 里面每一条都还没落地，别当成既有约定。
> 做完之后按性质并入真相源（决策/取舍 → `docs/设计决策记录.md`；规则/判据 → `AGENTS.md`；
> 用法/背景 → `README.md`），**本文随即 `git rm`**——规矩见 `AGENTS.md` §7「文档生命周期」。

## 1. 目标与动机

**动机**：型号有几十上百个，不可能一个一个建档（每个型号 = 一份档案 + 一次现场拍参考图
生成指纹，而参考图不入库，换机位重建时凭据就没了）。档案这条路在**数量级**上撑不住，
不只是"麻烦"。

**目标**：让"随便一个圆盘/圆环类零件"不建档也能量出尺寸——自动检出、自动换算、自动标到图上，
人读数。

**这不是一个功能，是一次定位变更**：现在这套东西更接近**检具**（告诉你合格吗），
要做的是**量具**（告诉你我在这些位置量到这些尺寸）。判断"这个数是什么"和"合格吗"
两件事都交回读表的人。

## 2. 现状盘点（已经有的积木，不必另写）

| 已有 | 在哪 | 能直接用吗 |
|---|---|---|
| 不建档试测的入口与语义 | `measure_ring.py` 的 `NO_PROFILE` / `IDENT_NOPROFILE`（`--profile none`） | 是，语义已经是"未验证 + 只给像素" |
| 直接指定换算系数 | `--mm-per-px`（`resolve_ratio` 里排第一位） | 是 |
| 外圈定位（自适应，不需要档案） | `find_outer` + `_outer_candidates` / `_outer_ok` | 是 |
| 内圈候选（多比例带 × 两种极性） | `_inner_candidates` / `_inner_ok` | 是，"列所有同心边"的候选生成器已经有了 |
| 亚像素射线找边 + 拟椭圆 | `find_edge_points`（带内取最陡梯度）/ `filter_and_fit` | 是，是积木 |
| "所有同心边"的原型 | `profile_ring.py`（Canny → 到圆心距离直方图 → 峰 → 半径/直径 px） | 只作原型：**圆心估计粗、边缘是像素级 Canny**，当诊断够用、当量具不够 |
| 结果唯一出口 | `measure_ring.measure()` → `RingResult`（CLI 打印、GUI 显示） | 是，新产出必须走它 |

**注意**：引擎内部本来就**不懂命名**——`find_edge_points` 找的是"给定半径带、给定极性下梯度最陡的点"，
`filter_and_fit` 把它拟成椭圆。标签是外层贴的。所以"不命名"是砍掉一层包装，不是砍功能。

## 3. 方案要点（倾向已定，但一条都还没落地）

1. **不命名**：报告只给"在半径 X 处检出一条边，直径 …px / …mm"，不声称它是外径还是中心孔。
   连带效果：不需要型号识别 → 不需要指纹库 → 不需要给上百个型号建档。
2. **图上标注是一等公民**：每条检出的边在图上画圈 + 带编号和数值的标签；同时画出"我认定的"
   与"我没认定的"（不同颜色/线型）。**选错边要从"静默地给一个数"变成图上看得见的画面。**
3. **换算系数提到机位级**：`mm/px` 是机位（+镜头+曝光）的属性，不是型号的属性。现在它存在
   每个型号档案里，是同一个数的多份真相源（旧的全局缓存 `models/mm_per_pixel.json` 已经因此退休）。
   提到一份，并在界面上显示**标定条件与时间**。
4. **放弃自动判定**：不命名就没有"外径"这个数可判 OK/NG。标称值本来就该来自图纸/工单
   （`--spec-*` 已经支持），通用模式不参与判定。
5. **判定用的标称值不进档案**：档案要记就只记"哪条边叫什么"（一份指认记录），
   不含标称值、不含系数。默认不记、一键可记。

## 4. 待定项（不解决就做不出来）

- **圆心从哪来（决定能测哪类零件）——已定（2026-10-23）：先只吃"外缘可见"的件。**
  圆心沿用 `find_outer`（已验证）。**这条边界要按"场景"说，不能按"型号"说**——2026-10-23 实测：
  型号2 那张回归夹具图（2026-10-07 旧机位：灰盘 + 白布）`find_outer` **是成功的**
  （外缘 54/72 点、`2605.1px`，与基线逐字符相同）；真正会让它失败的是 `part_profiles.json`
  里记的**另一个场景**（2026-10-22 的深色盘 + 黑背景）。所以低对比度**场景**不在射程内，
  遇到就如实报 `not_found`，别指望兜住。
  "不依赖外圈的圆心估计"（把"所有同心边的径向直方图最尖"当目标去搜圆心；`_coarse_centers` /
  `_radial_peaks` 是现成积木，`profile_ring.refine_center` 只是单波段雏形）**留作后续可选阶段**，
  等"外缘可见"这条稳定出数之后再评估——它是整个方案里唯一真正的新算法，也是最不确定的一块。
- **同一道边的两个面报一条还是两条？** 每条物理边都有极性（亮→暗 / 暗→亮）：外缘是一条带，
  有两个面；型号1 的内圈每圈是一道槽，也有两道壁（内壁/外壁差 1~2mm）。报两条 → 清单膨胀到
  十几条；报一条 → 就得引入"两道边夹一道槽取中点"的几何解释（一种轻量命名）。
  **当前倾向**：报两条、都标出来，由人看图取舍（图上标注让这个取舍变便宜）。
- **清单范围**：第一版是否只报**同心**尺寸（外圈 + 所有内圈），**螺栓孔不算**？
  螺栓孔不是同心边，且检测质量最差（缺陷 6：斜视档约一半沉孔被光打亮 → 只报 3 个）。
  **当前倾向**：第一版只做同心尺寸，螺栓孔最多画成"候选团块"、不报尺寸。
- **主次区分**：反光、加工纹路、零件下的阴影都会造边，图上会出现十几条圈。
  需要"边强度 / 点数"门槛，并在图上区分主次（强边实线、弱边浅色或虚线）。
- **图上排版**：型号1 的 55.9/60/78 三圈在 2000px 量级图上半径只差 40~140px，标签会打架。
  需要**引线 + 错位排布**。
- **GUI 缩放/平移**：现在结果图是缩略显示（`cv2.resize(frame, (self.view_w, ...))`），
  看不清内圈那几圈，要看细节得能放大。
- **顺带要查清的一个疑点 —— 已查清（2026-10-23）**：原疑点是两个档案系数
  `0.0436847`（型号1）与 `0.0446413`（型号2）差 2.2%。用两件的卡尺真值（**88.28 / 126.3**）
  和**同一种量法**（沿 72 条射线取内/外平台中位值的 50% 过阈半径）实测：

  | | 直径 | 同圈离散(P25~P75) | 真值 | 反推系数 |
  |---|---|---|---|---|
  | 零件1 | 2005.4 px | 1001.9~1003.9（±0.1%） | 88.28 | **0.044021** |
  | 零件2 | 2829.6 px | 1394.2~1433.6（**±1.4%**） | 126.3 | **0.044635** |

  **两个系数仍差 +1.40%**（在 126mm 上是 **1.74mm**）。而且**同一零件换量法也能差 0.9%**：
  零件1 用"带内最陡梯度"给 `2023.1px`、用"50% 平台中点"给 `2005.4px`。
  **结论：这 1~2% 不是标定错误，而是"外缘是一条有厚度的带"（`docs/已知缺陷.md` 缺陷 3）——
  不同零件/不同量法落在带的不同位置。**

  **对架构的意义**：
  - **"一个机位常数"可以用，但精度天花板是 ±1.4%**（126mm 上 ±1.8mm），与 `README` 的
    "冲 5 丝"差两个数量级。这个取舍要用户点头。
  - 档案里"每个型号各一个 `mm_per_px`"其实是在**为这个 1.4% 打补丁**——删掉档案换取"不建档"，
    代价就是这 1.4%。**必须让用户知情后再删。**
  - 零件2 的同圈离散比零件1 大一个数量级（±1.4% vs ±0.1%），说明它的边缘形态更"带"，
    更不适合当精密量具。

## 5. 落地路线：先建后拆

**总原则：先建新的，能出数了再拆旧的。** 用户明确允许"一段时间不可用、不着急用"，
所以**不必为保持可用而保留兼容层或双套输出**——这才是"允许停机"的真正价值，能让代码真减下来。
反过来，因为排成"先建后拆"，实际也能做到几乎不出现不可用窗口。

| 阶段 | 做什么 | 结束时能不能用 |
|---|---|---|
| 0 冻结基线 | 给当前 HEAD 打 `git tag`；两条夹具用例与参数已在 `AGENTS.md` §3 | 能 |
| 1 内核搬家 | 把下面"留"的那批（几何原语）整理进 §5.2 的布局，**不改任何行为** | 能（回归门仍是 §3 两条用例，px 必须逐字符不变） |
| 2 建新能力 | 写"定圆心 + 列同心边"（复用 `_inner_candidates` / `_radial_peaks` / `find_edge_points` / `filter_and_fit`）；旧路径还在，**可对拍** | 能（新旧并存，临时） |
| 3 换出口 | `RingResult` 改成候选清单形态 + 图上标注 + GUI 显示/缩放 + 换算系数提到机位级**一处** | 能（**新形态**） |
| 4 拆旧房 | 删 §5.1"删"那批；§3 的判据改成"清单里必须出现这些数"或按 §8 重定版 | 短暂不可用（旧路径已删；新路径阶段 3 已能跑） |
| 5 收尾 | 内容并入真相源、`git rm` 本文、数值重定版 | 能 |

**阶段 2 的对拍是关键安全网**：拆掉命名之前，先证明"新清单里包含老期望值"。但 2026-10-23 实测
发现**判据不能是逐字符相等**——通用扫描与老路径的测量定义不同（带宽更宽、没有 `id_mm/od_mm`
真值比锚定、`filter_and_fit` 的初值 `r0` 也不同），同一个物理边会算出略有差别的半径：

| 老期望值（`AGENTS.md` §3 用例1） | 清单里的对应项 | 偏差 |
|---|---|---|
| 外缘 2599.1×2826.7 | `#1` 2599.1×2826.7 | **0**（同一次 `find_outer`） |
| 内圈2 2384.2 | `#2` 2391.6 | +0.31% |
| 内圈1 1842.9 | `#12` 1849.6 | +0.36% |
| 中心孔 1778.0 | `#13` 1791.6 | +0.76% |

**所以对拍判据改为：每条老期望值都要有一个候选落在 ±1% 内**（外缘要求逐字符相等，因为它走的
是同一次 `find_outer`）。另外，"哪条候选对应哪个老值"目前只是我的初步推断，得等阶段 3 的标注图
让人对着看才能确认。

- **2026-10-23：纹理掩膜定带验证通过**（在零件2 那帧上离线做，未改代码）。做法：局部高通能量
  `E = sqrt(boxfilter((g-blur(g,σ=3))², 31))` → 以**背景能量**为基准做阈值（不用 Otsu）→ 最大连通域
  → 每条射线取掩膜最外半径 `r_mask` → 只在 `r_mask ± 半宽` 的带里找最陡下降边（门槛降到 0.5）。

  - **背景纹理能量 1.04 / 零件中心 19.1 = 18.3 倍**（背景取四角，纯黑且平坦，所以这个基准很稳）。
  - 掩膜阈值在 1.3~3.0 倍背景之间变化时，`r_mask` 中位从 1468px 变到 1323px（**±5%**）——
    因为纹理沿半径是**渐隐**的。所以**掩膜边界不能直接当半径用**。

  **结论：分工对了——纹理只负责"零件大概在哪"，亚像素找边负责"边精确在哪"。**

    点数不够就被判成拟合失败。**这是门槛太严，不是"边缘不存在"**：门槛降到 1.0 就能稳定拟合出直径
    `2840px`，而且**窗口挪 ±65px，直径只变 3px（0.12%）**，读数很稳。
    ⚠️ **先前记的"r=1411 与 1450 都能拟合成功 → 差 39px、会随窗口漂"是推断错误**：两个窗口都能拟合
    并不等于半径不稳；实测半径是稳的。以本次更正为准。
    预处理实测（同一帧，外缘带 r∈[1200,1600]、σ=5）：

    | 处理 | 外缘最大梯度中位 | 拟合直径（三个窗口） |
    |---|---|---|
    | 原图 | **2.00**（卡门槛） | 2838 / 2840 / 2840（跨度 3px） |
    | 全局拉伸 1~99% | 2.00 | 2839 / 2841 / 2841（3px） |
    | **局部归一化 `g/blur201`** | **5.00** | 2852 / 2852 / 2858（6px） |
    | CLAHE | 3.00 | 2846 / 2846 / 2846（0px） |
    | 锐化 unsharp | 2.00 | 2838 / 2841 / 2841（3px） |

    **结论**：局部归一化（`g / blur(sm,201)`，仓库里螺栓孔已经在用这个套路）能把梯度从 2.0 提到 5.0、
    稳过门槛；但**最省事的办法是把门槛降下来**（2.0 → ~1.0），因为边缘本来就是好的。
    注意**预处理会把读数整体挪 +0.5%**（2838 → 2852），属于测量定义变更（`AGENTS.md` §5），
    要走它就得连同所有读数一起重定版，不能悄悄加。物理补光仍值得做（为了内部的弱边），
    但**不是这一件能不能测的前提**。
    对照：零件1 在同样三个窗口下直径**跨度 0.0px**。

## 6. 已知代价与边界（不因本模式而消失）

- **模式量的是"边缘"，不是"尺寸"。** 报告不再回答"这个数是什么"和"合格吗"，两件事都在人这边。
  要说明白：这**不是取代人工**，是取代"建档"那一部分。
- **外缘那个坑还在**（缺陷 3）：外缘是一条有厚度的带，同一零件转 47° 检出外径 +2.5%。
  不命名之后它仍然存在，只是没有"外径"这个词来骗人——操作员会看到两个相近的数。
- **精度天花板不变**：单像素 ≈0.034mm；斜视误差是**位置相关**的，一个常数救不回来（斜视下
  不同位置 px/mm 不同）。`README.md` 的"冲 5 丝精度"是另一条路，要 5 丝仍然得针对该型号
  定义"量哪条边"。
- **几何前提是同心圆/椭圆**：矩形件、偏心孔、非圆件整条管线第一步就不成立。射程是
  "圆盘/圆环类零件，但不必预先建档"，不是"任何零件"。
- **缺档案时螺栓孔本来就不给毫米**（`bolts_unverified`），这跟"不命名"是同一个方向，不冲突。

## 7. 不做什么

沿用既有禁止项，不因本模式放宽：**不改 `od_mm` / `mm_per_px` 去凑读数**；
**不新增第三方依赖**；**不引入粗糙度分类线 / 棋盘格标定**；**不新建并列检测实现**；
**不动 `测量.bat`**。

## 8. 数值重定版（本轮全部落地后做）

现有回归期望值（`AGENTS.md` §3 那两张用例的表）在本轮改造全部落地后**重新定版**；在那之前
§3 是**过渡判据**（px 变了照旧算回归失败）。重定版时**用工具自己算、别手算**：
`--profile <型号> --image <该机位的图> --ref-mm <真值>`（理由见 `AGENTS.md` §3）。
数值仍然**只写 §3 一处**，别在 `README.md` 再抄一份。
