# 圆环测量：自适应定位改造计划

> **本文件 = "设计依据 + 决策台账"**：为什么这么改、参数怎么来的、试过并否决了什么、
> 回归用例的期望值。三分工：怎么用在 `README.md`、AI 规则在 `AGENTS.md`、
> 已知缺陷与停手条件在 `docs/已知缺陷.md` —— **同一件事只写一处，别在几个文件里各抄一遍**。
>
> 起因：换零件型号、或把零件挪出画面中心，就完全测不出尺寸。
> 本文记录 2026-10-07 起的排查结论、管线里写死的先验，以及分阶段的改造与落地记录。
> 读者：后续接手的人 / AI 助手。**本文件不写行号**：定位用符号名或可 grep 的原文片段

## 1. 结论摘要

三条，按重要性排：

1. **今天「测不出来」不是几何先验造成的，是那一帧几乎全黑。** 实拍帧灰度均值 16.7，
 外圈射线只能找到 3/72 个边缘点。自适应搜索救不了一张没有边缘的图——先解决光照/曝光。
2. **自适应改造要解决的是「换型号 / 挪位置 / 改机位」**，让像素检测不再依赖
 「零件在画面正中 + 外圈半径 = 短边的 44%」这类写死的假设。
3. **自适应**不**解决毫米读数正确性。** mm/px 是「相机+镜头+拍摄距离」的函数，而不同型号
 往往要换机位。现在它按型号存在 `models/part_profiles.json` 里（旧的全局缓存
 `models/mm_per_pixel.json` 已于 2026-10-08 退休删除）。挪了相机高度，检测能成功、毫米数
 照样是错的，必须对该型号重新标定。

## 2. 目标与非目标

**做**：
- 零件不在画面中心时能测。
- 零件在画面里变大/变小（相机高度变化、换外径相近的型号）时能测。
- 换型号时，孔数、孔径、孔径比、沉孔特征不再写死（靠型号档案 + 相对约束）。
- 失败时**说清为什么失败**（太暗？找不到外圈？还是锁定置信度不够？），而不是笼统一句
 「外圈拟合失败」。

**不做**（明确排除，避免后面的人误期待）：
- **不解决没光。** 全黑帧、过曝帧、失焦帧，任何搜索策略都无解，只能靠补光/曝光/对焦。
- **不提升精度。** 单像素 ≈0.0327mm，5 丝(±0.05mm) ≈1.5px；斜视成像、沉孔缓坡
 边缘定位误差 ±3~5px，**达不到 ±0.05mm**。自适应只改「能不能测出来」，不改「测得准不准」。
- **不引入第三方依赖**（AGENTS.md §4）。
- **不动** `测量.bat`。（`gui_ring.py` 后来为适配新状态改过显示层，不改数值；
 `models/mm_per_pixel.json` 已删除。）
- **不新建并列检测实现。** 几何算法一律改在 `fit_ellipse_ring.py`（AGENTS.md §6）。
 尤其**不要**从生产管线反向 `import profile_ring`——那会让管线依赖诊断脚本，方向反了
 （AGENTS.md §0 那条 gui_live 的教训）。

## 3. 现状诊断（2026-10-07 实测）

### 3.1 失败点

`debug\gui_error.log` 里当天的失败全是同一条，抛在 `measure_ring.measure()` 里那句 `raise MeasureError`：

```
MeasureError: 外圈拟合失败。检查：对焦、光照、零件是否在画面中心
```

调用栈是 `gui_ring.py::LiveSource._do_measure` 里的 `res = measure(frame, self.args)` → `measure_ring.measure()` → 那句 `raise MeasureError`。
即 `detect()` 的**第一关就返回了 None**（外圈拟合失败那个早退分支），
一个尺寸都没往下算。

### 3.2 实测证据

`gui_ring.py::LiveSource._do_measure` 在测量前会把相机原图存成
`data\captures\measure_ring_latest.jpg`（`_do_measure` 在测量前存的原图），所以那张失败帧还在。
拿它和标定图跑**同一份** `detect()`：

| 指标 | 标定图 `capture_20260908_115557.jpg` | 失败的实拍帧 `measure_ring_latest.jpg` |
|---|---|---|
| 分辨率 | 4024x3036 | 4024x3036（相同） |
| 灰度均值 | 109.7 | **16.7** |
| 暗像素(<40) 占比 | 3.4% | **99.1%** |
| 亮像素(>200) 占比 | 5.2% | **0.0%** |
| 72 条射线找到的外圈边缘点 | **72 / 72** | **3 / 72** |
| `detect()` 结果 | 外圈拟合成功 | 外圈 = None |

`filter_and_fit` 需要 ≥20 个点才拟合（它的 `min_pts` 默认值），3 个点直接判 None。
把那张帧调亮后目视确认：**零件确实在画面里、也基本居中**（就是那个带 6 个沉孔的法兰），
所以不是「零件不在视野」，纯粹是曝光不足。

### 3.3 时序：不是本次重构引入的

- 该错在 **15:56:03 / 15:57:18~15:57:30** 已批量出现，**早于**当天 16:50 起的任何代码改动。
- `gui_error.log` 里还有 **2026-09-18 11:18:24** 与 **2026-09-21 15:15:15** 两条同类失败
 （当时日志只记到 `NoneType: None`，是后来 commit `52e84d4` 才修好的日志缺陷）。
- 结论：这是**反复出现的老问题**，与 commit `2880d9d` 的三项清理无关——那三项已用
 「改前改后 CLI 输出逐字符一致」验证过（见该 commit 的 message）。

### 3.4 立即要做的（不属于本次改造，但挡在改造前面）

`src/config.py` 当前 `exposure_us=30000.0`、`gain=0`。要么现场补光，要么提高曝光
（150~200ms 起步）或加 gain，然后拍一张走 CLI 验证能出数：

```bash
cd vision-roughness
venv\Scripts\python.exe src\measure_ring.py --image ..\data\captures\<新拍的图>.jpg
```

### 3.5 一个会误导人的地方

窗口里的「预览增亮 ×3」**只作用于缩略图副本**（`LiveSource._encode` 里的 `cv2.convertScaleAbs`，
`convertScaleAbs(small, alpha=3.0)` 作用在 resize 之后的 `small` 上），测量永远用相机原始
亮度。所以它会把一张 mean=16.7 的全黑帧显示成"灰蒙蒙还能看"，**别拿预览画面的亮度当
"曝光够不够"的依据**。这条建议写进 README 的操作说明。

## 4. 改造前的测量逻辑全景

> **本节是 2026-10-07 改造前的快照**，用来说明"当时写死了什么、为什么会坏"，**不是现在的行为**。
> 现在的行为见 §6 的 Phase 1/2/3 与「架构重构」两节。

`measure_ring.measure()` 调 `fit_ellipse_ring.detect()`，
四步，每步都带硬先验：

### 4.1 外圈（`detect()` 里的外圈段）

1. `sm = GaussianBlur(gray, (0,0), 5)`——σ=5 固定。
2. 从 **图像中心** + 初始半径 `min(w,h)*0.44` 起（`cx0, cy0 = init_c or ...` 与那三档 `r0`），失败再试 `0.40`、`0.48`
 共三档。
3. 每个半径：72 条射线，在 `[0.88·r0, 1.16·r0]` 窗口内找**最外侧的下降沿**
 （`mode="outer_first"`，`polarity=-1`，`min_grad=2.0`）。
4. `filter_and_fit`：用"圆等价归一化距离 9%"（`outlier=0.09`）滤离群点，`cv2.fitEllipse` 迭代 3 轮。
5. 精修：以粗椭圆中心/半径，紧窗口 `[0.93·req, 1.07·req]` 再采一轮。

**这是当前唯一的"全废"点**：这一关过不了，整个测量返回空（外圈早退分支）。

### 4.2 中心孔（`detect()` 里的中心孔段）

以**外圈中心**为原点，在 `[0.60, 0.78]·r_outer` 内找**上升沿**（暗→亮，`polarity=+1`，
`min_grad=1.2`），同一套鲁棒拟合，内点半径锚定在 `0.7·r_outer`。
即**孔径/外径比写死在 0.60~0.78**。

### 4.3 螺栓孔（`detect()` 里的螺栓孔段）

1. 环带：外圈椭圆 ×0.98 与中心孔椭圆 ×1.05 之间。
2. 局部对比度归一化 `norm = sm / max(blur(sm,(201,201)),1)`。
3. `rough_templates` 在环带里找暗连通域（`norm<0.62`、面积≥3000px²、圆度≥0.55），
 挑最像的当模板（±125px 窗口，强制 resize 到 250×250）。
4. `template_locate`：缩 3 倍做 `TM_CCOEFF_NORMED` 匹配，峰阈值 0.30，
 抑制半径 150px，最多取 12 个峰。
5. 候选过滤：距外圈中心必须在 `0.5~1.05·r_outer`，且在 `(40,140)` 环带内
 找到 ≥12 个边缘点。
6. `hexagon_slots`（重构后叫 `ngon_slots`）：**当时固定 6 个孔、固定 60° 间隔、等归一化半径**，容差
 `tol_ang=13°`、`tol_r=0.15`；缺位按等角等半径推定。
7. 每个槽位 `measure_bolt`：`hole_head_center` 锚定螺丝头（win=160,
 thr=0.72）→ `_head_radius` 估头半径（12 方向，clip 到 0~60px）→
 `rim_cross_points` 找第一个宽度≥12px 的连续暗游程，取末端 **0.72 亮度阈值交叉点**
 作为沉孔口边缘（`rim_cross_points`，72 射线，max_r=150）→ `fit_clean_arc` 极化残差鲁棒椭圆拟合
 。
8. 二遍校正：以拟合中心重采一轮再拟合（`measure_bolt` 内）。

> 领域提醒（读数怎么解读见 README「已知限制」）：螺栓孔测的是**沉孔口口径**（含沉孔锥度），**不是螺纹孔径**。
> 6 孔读数分散 154.5~176.3px ≈ ±7%，**不得据此判定尺寸超差**。

### 4.4 换算与判定

- `mm = px × mm_per_px`，`mm_per_px` 当时是全图唯一常数（`resolve_ratio` 里那一个标量），
 来源 `--mm-per-px` / `--ref-mm` 标定后写回型号档案 / 读该型号档案的 `mm_per_px`。
- `tilt = max(oa1,oa2)/min(oa1,oa2)`，>1.02 就提示透视。
- **不传 `--spec-*` 时 `overall_judged=False`**，CLI 仍打印「综合判定: OK」——这个 OK
 不是合格判定（AGENTS.md §5）。
- 贴边检查 `BORDER_MARGIN = 5`。

### 5.8 三条走查结论

1. **`init_c` / `init_r` 是从未被注入的死参数**（`detect()` 定义，外圈那三档处读取；
 全仓调用点只有 `fit_ellipse_ring.main()` 与 `measure_ring.measure()`，都没传参）。
 → **这是自适应改造最现成的注入点。**
2. **仓库没有任何"型号 / 档案 / preset"概念**（grep `型号|profile|preset|nominal|part_type`
 只命中 `--spec-*` 单组标称值、当时那个全局标量缓存，
 以及 `profile_ring.py` 里表示"径向剖面"的 profile）。Phase 3 要从零建。
3. **`profile_ring.py` 里已躺着一整套自适应原语，但主流程从未采用**：
 `coarse_center`（边缘密度质心）、`cross_projection`（行/列投影峰定外圈 box）、
 `radial_hist`（径向距离直方图）、`find_peaks`（多半径峰）、
 `refine_center`（网格搜索最大化峰高精化圆心）。
 `edge_ring.try_hough` 另有 HoughCircles 多档 `param2` 扫描；`explore_ring` 有
 Otsu + 最大轮廓 + `minEnclosingCircle`/`fitEllipse`。
 → **借做法，不要借代码**（见 §2 的依赖方向约束）：把这些原语在 `fit_ellipse_ring.py`
 里实现，`profile_ring.py` 保持诊断脚本身份不变。

## 6. 分阶段计划

原则：**先位置后型号**（你选的），**混合方案**——位置/尺度靠数据自适应，
语义先验（孔数、孔径比、标称值）靠型号档案。每阶段独立可回归、可回退。

### Phase 0：先建验证手段（不改生产代码）

现在仓库只有一张能用的标定图，无法判断"自适应到底找准了没有"。
AGENTS.md §6 明确要求**调参前必须先看数据**。

### Phase 1：外圈自适应定位（收益最大）—— 方案与可行性验证

**做法**：新增"数据驱动粗定位"阶段，**现有的射线亚像素 + 鲁棒椭圆拟合一行不动**——
那部分已验证，只是"从哪儿开始找"写死了。

在 `src/fit_ellipse_ring.py` 内新增：

1. `_edge_map(sm)` —— Otsu 定阈值 → `Canny` 取边缘图（配方沿用 `profile_ring.main` 里那几步）。
2. `_coarse_centers(edges)` —— 给出**多个**候选圆心而非只有图像中心：
 图像中心（保底）、`cross_projection` 式投影峰交点、边缘密度质心。
3. `_radial_peaks(edges, cx, cy)` —— 径向距离直方图 + 峰检测，得**若干候选半径**，
 替换写死的 `0.44/0.40/0.48` 三档。
4. 候选集 = `[旧先验(中心, 0.44×短边)] + [候选圆心 × 候选半径]`，**旧先验排第一**。
5. 每个候选走**现有**的 `find_edge_points(mode="outer_first")` + `filter_and_fit` + 紧窗口精修。
6. `_score_outer(...)` 硬门槛（模块级常量，便于调）：
 - 保留点数 ≥ `0.6 × 72`；
 - 角度覆盖无 >40° 的空洞（按射线角度分箱）；
 - 点到椭圆径向残差 RMS ≤ 3px（或 ≤ 半径的 0.3%）；
 - 长短轴比 ≤ 1.8，且椭圆不出画幅。
7. 选分数最高且过门槛者；**全不过就照旧失败**（保留诚实的 `MeasureError`），
 绝不在低分下硬给一个数。

**可行性已实测（2026-10-07，标定图，命令见附录 3）**：真实外圈中心为
**(1974.6, 1516.7)**，各粗定位原语给出的结果：

| 粗定位手段 | 结果 | 与真实中心距离 |
|---|---|---|
| `cross_projection` 投影峰 box 中心 | (1964, 1588) | **72 px** |
| `coarse_center` 边缘密度质心 | (2082, 1676) | **192 px** |
| 写死的图像中心（现状） | (2012, 1518) | 37 px |
| 径向直方图最强峰 | r=1305px（∅2610） | 与真实短半轴 2599.1 差 **0.4%** |

两个结论，直接决定 Phase 1 的做法：

1. **「用径向峰找外圈半径」这条路线成立**——最强峰和真实外圈只差 0.4%。
2. **但没有任何单一粗定位够用**：投影峰偏 72px、质心偏 192px，而采边窗口
 `[0.88, 1.16]·r0` 对 r0=1336 只给 **±160px** 余量——质心那种偏差会直接把窗口下界切掉。
 所以必须**多候选 + 图像中心兜底 + 打分选优**，而不是把某个粗定位结果直接替换进去。

**决定性实验（2026-10-07，型号 2 实拍 `capture_single_20261007_203729.jpg`，曝光已修好）**

盘心 (1412,1589)、画面中心 (2012,1518)——**偏了 604px**。同一张图、同一份 `detect()`：

| 喂给 `detect()` 的先验 | 结果 |
|---|---|
| 现状（图像中心 + 0.44×短边） | 外圈拟合**失败** |
| 注入 `init_c` / `init_r`（Otsu 粗定位） | 外圈「OK」：2962.9x3118.6px，但**只用上 22/72 个点** |

**看似通了，其实是误锁。** 真实盘径（径向峰 r=1289、峰宽仅 6px）是 **2578px**，
而这个拟合的均值直径 **3040px（大了 18%）**，外接框还**溢出画幅**
（x 到 −48、y 到 3174；画幅 4024x3036）。两条结论：

1. **先验确实是唯一的拦路石** —— 把它换对，检测立刻从「失败」翻成「通过」。
2. **但"随便给个粗定位"不够，反而更危险** —— 它会给出一个看着成功、实际偏大 18% 的椭圆。
 Phase 1 那几道门槛不是保险起见，是**必需品**：本例里「点数 ≥0.6×72」（22 < 43）
 和「椭圆不出画幅」任意一条都能把它挡下来。
 这也正说明为什么必须先有 Phase 0 的真值表——没有真值，你分不出「OK」和「误锁」。

**基线保护（关键）**：旧先验排首位 ⇒ 标定图必然走原路径，读数应逐位不变。
等 Phase 0 数据到位后再切"纯按分数选优"（Phase 1b），并确认标定图仍不变。

**顺带并入（约 10 行，直接解决今天的报错质量）**：`detect()` 前加亮度门——
动态范围太小时明确报「画面太暗（均值 x/255），先补光或提高曝光」，
而不是含糊的「外圈拟合失败」。

### 架构重构：拆掉 `feature` 枚举，改成两个正交维度（2026-10-08）

起因：`feature: countersink|core_hole` 把**两个本来独立**的决定压成了一个枚举——
「怎么定位孔」和「量哪条边界」。后果是组合爆炸：一旦出现「已知 4 孔角度 + 沉孔口边界」
这种组合，就得再加一个 feature 值、再抄一遍代码。而且代码的默认路径就是型号1 的样式，
等于把某一个具体产品固化成了系统的默认语义。

改法：拆成 `locate` + `boundary` 两个字段（各配一张策略表），**所有型号平级**：

| 维度 | 取值 | 说明 |
|---|---|---|
| `locate` | `profile_angles` / `template_ngon` | 按档案角度+相位搜索 / 暗斑模板匹配+n 等分校验 |
| `boundary` | `countersink_rim` / `dark_core` | 沉孔口阈值交叉 / 暗芯中分界 |

新组合（比如「4 孔沉孔」）现在**零代码**；全新形态（比如通孔）只加一个 boundary 函数（约 15 行）。

一并解决的几件事：

1. **孔数不再写死**：`ngon_slots(n=bolt_count)`；档案没给就用 `infer_ngon_n` 从候选峰推断。
 实测原来写死 6 时，12 孔零件下 6 个槽位**全被真孔填满、一个都不留空**——于是静默只报 6 个。
2. **推定位置标出来**（`src=detected|profile|synthesized`）：标定图里本来就有 1 个推定位置
 （螺栓孔5），以前和实测孔长得一模一样，现在报告写「← 位置推定」、GUI 加 `?`。
3. **中心孔没检出时螺栓孔照样跑**，不再整段跳过——那条「没检测到螺栓孔」的误导随之消失。
4. **全局缓存 `models/mm_per_pixel.json` 退休删除**：它是同一个数的第二份真相源，而且属于
 「上次标定的某个型号」。现在系数只存在型号档案里；查不到就**只报像素、不给毫米**。
5. **不传 `--profile` 时按 `_默认型号` 兜底**（是数据，不是隐藏的代码路径），所以车间入口
 （`测量.bat` 不传参）照旧能用；`--ref-mm` 改为**必须显式带 `--profile`**，
 免得它落到默认型号、把那个型号的系数悄悄改掉。
 （**注：`_默认型号` 已于 2026-10-08 删除**，见下面「型号识别」一节的落地记录——
 那是识别还没做成时的拐杖，留着它会在识别失败时拿错型号的标称值给出一个"理直气壮"的错读数。）

验证：默认型号路径的**读数行与重构前逐字符一致**；型号2 读数不变；15 项自测全过。

### 型号识别（自动为主、人工兜底）—— ✅ 已落地（2026-10-08，极坐标指纹）

**要解决的问题**：以后型号多，不该让人每次去选型号；人工选择只作最后的兜底。

**为什么能用指纹识别**：绝对尺寸不行——`mm_per_px` 本身是按型号存的，拿绝对外径去查档案是
循环依赖。有用的必须**无量纲**：环带按**归一化半径**展开、整张指纹再标准化，于是尺度/亮度/
对比度都不影响匹配；沿角度做**循环互相关**，旋转不变性也是免费的。全程只依赖一个几何量：
外圈椭圆。指纹落在 `models/fingerprints/<型号名>.npz`（入库），用
`--image <参考图> --profile <型号名> --save-fingerprint` 生成/覆盖。

**前一条路线为什么废掉（实测，别再走）**：原来那版"通用第一遍"取指纹（孔数/有无中心孔/
孔圈半径比，函数 `build_signature`/`match_profile`，**已删除**）实测命中率为 0：

- **型号2**：通用定位走暗斑模板匹配，要求暗斑面积 ≥3000px²（等效直径 ≥61.8px，**绝对像素
  门槛**），而型号2 的暗芯只有 ~37px，**第一关就被挡掉**，孔数=0 → 无法识别。
- **型号1**：孔数推断被盘面上的假峰带偏，推出来的 n 不是 6 → 指纹对不上。

也试过"不带型号先验"的圆特征查找器（环带内紧凑暗块、尺寸窗口用相对外径的比例），型号1 只找到
**1/6** 个、型号2 **3/4** 个：局部对比度归一化的窗口（201px）和型号1 的沉孔尺寸（~170px）量级
相当，等于把特征自己归一化掉了。**用绝对像素尺寸做判据、或者靠特征查找，这两条路都别再走。**

**落地过程中实测出来、写进代码注释与 AGENTS.md 的四件事**：

1. **径向基准不能是"拟合椭圆"**。外缘是一条**有厚度的带**（倒角/圆角 + 斜视下有的角度亮、
   有的暗），拟合椭圆随零件转动在带内漂：型号1 转 47° 时外径 2712.9→2780.3px（+2.5%）＝
   把 720×64 的指纹沿半径整体错开约 9 列，自匹配从 1.0 掉到 **0.15**，与交叉得分（≤0.148）
   **重叠**、判不开。改成**每条射线各自锚定它自己量到的外缘**（`_outer_edge_anchor`）后，
   自匹配最差 0.463、交叉最高 0.078，可分。
2. **逐射线的锚点会抖动**（最强梯度在带的两侧之间来回跳，实测 std≈0.042×r_ell）。椭圆的极坐标
   半径本身是 θ 的**纯二次谐波**函数，所以对 720 个锚点做**谐波 0/2/4 的傅里叶拟合**
   （`_smooth_anchor`）——这一条是旋转不变性能用的关键（不平滑时自匹配在 47°~317° 掉到 0.15）。
3. **试过并否决**：半径方向平移取最优（救不回来，且把交叉从 0.07 抬到 0.18）；逐列（每个半径）
   去均值（交叉从 0.043 爆到 0.254，模型间裕度崩掉）。
4. **扰动矩阵（工装错了矩阵就无效）**：只转零件（椭圆掩膜合成）、**背景不动、画幅尺寸不变**
   ——绕画面中心转整图会把零件切出画幅；裁方幅会改变"半径≈短边44%"的先验、让外圈**误锁**；
   连背景一起转会带跑自适应粗定位（型号2 在 12/14 个角度定位失败）。缩放/亮度/噪声则相反：
   那是"相机或光照变了"，整张图一起变才对。
   结果：47 个扰动版本（14 个旋转角 × 缩放 0.85~1.18 × 亮度 0.7~1.4 × 噪声 σ5/12）
   **零认错**，自匹配最低 0.373、交叉最高 0.078（门槛 `FP_ACCEPT=0.30` 落在中间）。
   ⚠️ **两条验收不能互相替代**：验收 2（型号2 不传 `--profile` 能识别）**其实是自匹配**——
   两张参考图本来就是两个型号各自的建档图，认出它们**不证明泛化**。真正的泛化证据只有上面
   这个扰动矩阵，而它也只是合成扰动、不是新零件实拍。拿到第三个零件的实拍之前，别把
   "两个型号都识别对了"当成就绪证据。

**⚠️ 两条如实记录的限制（别当成已解决）**：

- **门槛与参数只在 2 个零件上标定过**（型号1/型号2 各一张参考图），属**暂定值**；
  **拿到第三个零件必须复核**。这两个数不许为了让某张图认得出来去调。
- **指纹的信息量集中在最外那几圈（外缘带），盘面贡献很小** —— 所以"不同型号之间"分得很开
  （交叉 ≤0.078），但"是不是这个型号"判得偏松。**具体证据（平盘/垫圈被误认、以及两个试过并
  否决的修法）见 `docs/已知缺陷.md` 的缺陷 5**，此处不重复。要根治得改"判据里算哪些结构"。

**2026-10-08 现场实测（GUI，最重要的反证）**：同一套代码、同一时刻，**型号2（4 孔平面盘）
7/7 全部自动认出**（0.879~0.892），而**型号1（6 孔车削环）0/25**（0.144~0.260，全在门槛下）——
差别在零件本身。逐层排查（不是取景、不是外圈锁错、不是机制坏、不是姿态单独造成、不是光照强弱、
不是极性反了）后定位到**真因：判据比的是"表面明暗纹理"而不是"孔的位置"**——指纹的方差
**54%（标定图）/ 69%（实拍帧）集中在外缘那 24% 的半径带**里，而车削件那一圈的外观随光照/朝向
整个会变（逐列相关最好的一列只有 +0.153）。
**完整证据、影响与修复方向见 `docs/已知缺陷.md` 的缺陷 2**（诊断脚本留档在 `vision-roughness/temp/`：
`diag_6hole.py` / `diag_polarity.py` / `diag_pose_vs_light.py` / `diag_geometry.py`），此处不重复。
**修法方向**：把判据换成**几何量**——首选"孔环的角度签名"（在孔环半径处沿角度找暗斑：沉孔无论
怎么打光都比周围暗，于是得到"几个孔、相隔多少度、什么归一化半径"），对光照/朝向天然不敏感，
还顺手把"是不是这个型号"该看的孔数/角间隔纳入判据；次选"极坐标图先去掉沿角度的低频再相关"。
**这一条与"平盘也被接受"是同一个根因，一个修法同时治两个缺陷。**

**识别失败不再兜底**：`_默认型号` 已删（它是识别命中率为 0 时的拐杖，风险是识别失败时拿默认
型号的标称值和 mm/px 给出一个理直气壮的错读数）。现在识别失败 = 与 `--profile none` 同一语义：
**只给像素、标「未经验证」、提示人工选型号**（`gui_ring.py` 顶部新增「型号」下拉框：
自动识别 / 各型号 / 无档案试测；`测量.bat` 一个字未改）。

### 另记：零件转角下**检出尺寸**会变（另一轮，未做）

**机理**（这才是它留在这个文档里的原因）：零件外缘是**一条有厚度的带**（倒角/圆角 + 斜视下有的
角度亮、有的暗），`filter_and_fit` + `_refine_outer` 会随转角落到带的不同位置上。所以任何
**以检出外圈为基准**的东西（含极坐标指纹的径向基准）都要考虑这件事——正是它逼出了指纹里
"每条射线各自锚定外缘 + 傅里叶平滑锚点曲线"那两步（见上面「型号识别」）。
**不是本次改造引入的**（指纹只是"读"外圈椭圆，不改它），也不该靠调门槛去掩。
**实测数据（各转角的外径/中心孔漂移量）、影响与"另一轮"的重开条件见 `docs/已知缺陷.md` 的缺陷 3**。
在那之前：**同一零件不同转角的读数不可互比**，也不得据此判超差。

### 内圈：按两道边的中点（2026-10-22）

型号1 的 ~60/~78 两圈在图上各是一道**环形槽**（内壁亮→暗、外壁暗→亮，两条边差 1~2mm），
卡尺真值落在两条边中间。所以 `_measure_inner_rings` 对每圈分别找两条边、各拟一次椭圆、
取中点；档案 `inner_rings` 里的 `mm` 只用来圈定搜索带（`mm/od_mm` ±3.5%）和显示偏差。

实测（2026-10-22 新机位、近正对 2.8°）：

| 圈 | 中点读数 | 真值 | 偏差 |
|---|---|---|---|
| 内圈1 | 60.246mm | 60 | +0.41% |
| 内圈2 | 78.187mm | 78 | +0.24% |

回归用例 1（23° 斜视）的内圈 px 是 1842.9 / 2384.2；按该图自己的系数（0.032540）折回是
59.97 / 77.58mm，与真值一致。**外圈 / 中心孔 / 各孔的 px 均未变**。

**只做加性测量**：找不到一正一负两条边就标「未测到」，绝不拿一条边硬充中点。

## 8. 风险与对策

| 风险 | 对策 |
|---|---|
| **误锁（量错圈）比测不出来更糟** —— 操作员会拿着错数当真 | 硬门槛 + 必须报告"选了哪个假设/尺度/置信度"；低分绝不静默出数 |
| **基线漂移** —— 车间在用的这款零件读数变了 | 旧先验排候选首位；标定图回归门；逐阶段交付 |
| **实时性** —— 粗定位拖垮 7.7fps 取景 | 粗定位跑降采样图（Canny + 直方图），且仅在快速路径失败时才启用；预算 ≤100ms |
| **仓库没有测试框架**（AGENTS.md §3） | Phase 0 的评估脚本是替代品，但只放 `temp/`，不变成隐性新依赖 |
| **改完仍测不出，以为是改造没生效** | 先过 §3.4 的曝光/补光这一关；亮度门会把这种情况单独报出来 |
| **有人顺手引入平滑"提精度"** | AGENTS.md §6 已记：梯度算在未平滑剖面上，加平滑就是改所有读数 |
